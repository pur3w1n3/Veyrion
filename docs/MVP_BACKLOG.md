# 溯脉 · Veyrion MVP 开发任务拆解

产品正式名称为“溯脉 · Veyrion”（英文：Veyrion）。`com.aq.jvmsentinel` 包名、Maven artifactId、内部 service name 和 `/api/v1` 路由保持兼容；商标和域名尚需检索。

## 1. MVP 目标

完成一个可演示、可复现的纵向闭环：

```text
导入 Spring Boot JAR/WAR
  → 前置 AI 识别入口/业务/依赖
  → 启动隔离沙箱
  → 执行 HTTP 路径探索
  → 记录污点和数据库表字段
  → AI 分析风险
  → 串联至少两类漏洞
  → GUI 展示证据和报告
```

第一版聚焦 JVM、HTTP 和本地依赖替身，不把 WebSocket、多语言和真实生产连接纳入 MVP 的必选范围。

> **MVP 口径说明**：单独的 CLASS 文件通常无法启动完整应用。没有可运行的 classpath、配置和启动入口时，CLASS 仅承诺静态分析；动态路径探索的验收对象必须是可启动的 JAR/WAR（或用户提供完整运行画像）。WebSocket 适配器在 M1 可保留接口占位，但不计入 MVP 验收覆盖率。

> **GUI 口径说明**：GUI 与 Java 分析核心解耦，MVP 使用 React/TypeScript/Vite；Java 只提供版本化 API 和事件流。Tauri 桌面包装、WebGL 大图谱和多人协作不属于 MVP 必选项。

## 2. 版本边界

### 必须支持

- JAR/WAR/CLASS 导入；
- Spring Boot/Spring MVC 基础入口；
- HTTP 请求生成和 Session；
- 文件、路径、命令、SSRF、反序列化相关 sink 的识别；
- 数据库 Mock、JDBC 访问记录和表/字段血缘；
- 方法调用、分支和污点轨迹；
- 入口地图、路径时间线、漏洞详情和攻击链页面；
- 任务暂停、恢复、重放和审计；
- 本地模型或 OpenAI-compatible 模型接入；
- 扫描范围和危险操作策略。

### 暂不纳入

- 任意语言支持；
- 无限制真实外部网络访问；
- 自动破坏性利用；
- 复杂分布式集群的全量一致性；
- 100% 路径覆盖承诺；
- 面向生产系统的主动攻击模式。

## 3. 里程碑与任务

### M0：基础骨架与安全策略

**M0-01 项目和制品模型（P0）**

- 建立 Project、Artifact、Scan、Task、Evidence、Finding 基础表。
- 制品哈希、版本和生命周期可追踪。
- 验收：同一制品重复导入可识别为同版本，扫描结果不会互相覆盖。

**M0-02 授权与扫描策略（P0）**

- 实现授权确认、网络白名单、资源上限、只读/dry-run 策略。
- 所有危险操作写审计日志。
- 验收：未确认授权或超出白名单时，任务无法启动。

**M0-03 Worker 与任务队列（P0）**

- 支持任务创建、状态流转、取消、重试和恢复。
- 验收：Worker 异常退出后任务可从最近快照恢复。

### M1：制品接入与前置 AI

> **范围修订**：MVP 面向个人本地使用。完整多租户/RBAC、SSO、跨租户调度以及真实供应商生产互操作取消，不再作为本版里程碑或验收条件。动态验收必须依赖用户授权的沙箱，未获授权或沙箱不可用时保持 fail-closed。六个 AI 角色固定按 [AUDIT_FLOW.md](AUDIT_FLOW.md) 推进（含 `AUTH_ANALYSIS`）；路径实验契约见 [PATH_EXPERIMENT_MODEL.md](PATH_EXPERIMENT_MODEL.md)。提示词支持中英文项目级编辑并在 Job snapshot 中固化。

### M-A：PathRun 契约与呈现（P0）

- 引入 PathRun / 实验计划 DTO、超时分类枚举、`DYNAMIC_CONFIRMED` 验证状态（API + 前端 labels）。
- 探针/Agent 将传输与业务失败打到最小超时枚举，减少笼统 `UNKNOWN`。
- GUI 结果主视图按入口×轨展示 PathRun；`AUTH_GAP` 降为次级信号。
- 验收：DTO 含新状态；结果页可筛选 `DYNAMIC_CONFIRMED`；旧 scan 兼容展示。

### M-B：鉴权分析、合成身份与按轨观察（P0）

- `AUTH_ANALYSIS` 角色绑定与流水线 P1+P3（洪水前分析 + 动态后绕过确认）。
- 平台合成身份（JWT 等推断材料）；失败轨 `IDENTITY_UNAVAILABLE`。
- AI 生成实验计划 → 服务端闸门 → 按轨执行（T2+T3 预算）。
- 验收：baldex 上 ADMIN 轨可携带合成 Token 探测；PathRun 含轨与身份 provenance。

### M-C：SQL D1–D3 与 DYNAMIC_CONFIRMED（P0）

- JDBC/替身插桩记录 SQL 事件到 PathRun（D1）；差分探针（D2）；可重放实验卡（D3）。
- 服务端 H3 门禁升 `DYNAMIC_CONFIRMED`；模型不能单独升级。
- 验收：含 SQL 的入口出现 D1；受控差分可达 D2/D3；仅恶意片段无过滤入库时出现 `DYNAMIC_CONFIRMED`。

### M-D：高价值语义包 Blade/Flowable（P1）

- Blade JWT 默认证件 AnalysisPack；Flowable deploy/multipart 实验形态（无破坏、无内存马）。
- 验收：PDF 链的可观测子集（合成身份过闸、deploy 路径实验、SQL 分级），不承诺内存马或 `VERIFIED`。

**M1-01 JAR/WAR/CLASS 解析（P0）**

- 提取 MANIFEST、依赖、配置、注解和类清单。
- 保存反编译视图与字节码定位信息。
- 验收：能够列出示例项目的类、方法、主类和 Java 版本。

**M1-02 Spring 入口适配器（P0）**

- 识别 Controller、RequestMapping、Filter、Interceptor 和 WebSocket 预留接口。
- 生成初版 EntryCatalog。
- 验收：HTTP 方法、路径、参数和认证注解可在 GUI 查询。

**M1-03 业务理解前置 Agent（P0）**

- 输入反编译代码、静态图和配置。
- 输出 BusinessFlow、PermissionMatrix、DependencyMap、SinkCatalog 和 ExplorationPlan。
- 验收：每项推断都带来源和置信度；能识别数据库表/字段候选。

**M1-04 依赖和状态模型（P1）**

- 建立身份、租户、业务状态和外部依赖的结构化模型。
- 验收：入口详情页可显示“需要角色/租户/状态”的前置条件。

### M2：沙箱与运行时观测

**M2-01 隔离运行器（P0）**

- 每次扫描独立容器；限制网络、CPU、内存、磁盘和进程。
- 验收：应用无法访问未授权网络和宿主机路径。

- 发布门槛：容器必须使用非特权用户、只读根文件系统、最小 capabilities 和系统调用过滤；沙箱逃逸、宿主机路径读取和资源耗尽测试全部通过后才允许进入动态扫描。

**M2-02 JVM Agent（P0）**

- 采集方法、异常、分支、文件、网络、进程和反射行为。
- 实现采样、过滤和敏感值脱敏。
- 验收：一次请求可生成带调用栈和时间戳的完整轨迹。

**M2-03 JDBC 代理与数据库 Mock（P0）**

- 拦截 SQL、记录库表字段和读写类型。
- 支持空结果、边界记录、异常和事务回滚。
- 验收：数据库不可用时业务仍可执行到后续逻辑；报告明确标注“依赖已模拟”。

**M2-04 HTTP/文件/时间替身（P1）**

- 提供 Mock HTTP、临时文件系统、可控时间和随机种子。
- 验收：同一任务可以重放并得到一致轨迹。

### M3：路径洪水与回溯

**M3-01 基础输入生成（P0）**

- 根据参数类型、注解和运行时错误生成合法输入、边界值和结构化请求。
- 验收：支持 JSON、表单、Query、Path、Header 和文件字段。

**M3-02 覆盖率反馈队列（P0）**

- 以新分支、新方法、新 sink 距离和状态变化计算任务优先级。
- 验收：新输入能够被自动加入队列并显示覆盖率增量。

**M3-03 约束失败回溯（P0）**

- 保存快照、父路径和分支约束。
- 遇到类型、权限或状态失败时生成替代输入/身份并重放。
- 验收：至少一个需要特定权限或业务状态的示例路径可继续执行，并在结果中标注前置条件。

**M3-04 非终止和资源保护（P0）**

- 实现时间、指令数、状态重复和资源上限。
- 验收：超限任务安全停止，并显示 stopReason 和未覆盖节点。

### M4：AI 分析与全局串联

**M4-01 数据流分析 Agent（P0）**

- 根据静态图和动态轨迹输出 source/transform/sink 结构。
- 验收：能够解释一次文件名从入口到文件操作的完整流向。

**M4-02 漏洞判定 Agent（P0）**

- 首批支持路径穿越、任意文件写入、SSRF、命令执行和反序列化疑点。
- 验收：结果包含 CWE、证据引用、前置条件、置信度和验证状态。

**M4-03 中枢知识图谱（P0）**

- 持久化入口、参数、方法、字段、sink、finding 和 evidence 关系。
- 实现去重和跨入口查询。
- 验收：可查询“哪些入口写入 attachment.path 字段”以及“哪些入口可到达 ProcessBuilder”。

**M4-04 攻击链关联与验证（P0）**

- 以共享资源、文件、路径、身份和数据流为关联条件生成候选链。
- 仅将可重放链标记为已验证。
- 验收：示例项目中上传、路径获取和执行三个接口可以在一张图中串联。

### M5：GUI 与报告

**M5-01 项目总览和入口地图（P0）**

- 显示扫描进度、入口、覆盖度、依赖和风险。
- 支持按协议、模块、权限和风险筛选。
- 前端使用 React/TypeScript，所有数据来自版本化 API，不直接访问存储层。

**M5-02 路径探索器（P0）**

- 展示请求、参数、调用栈、分支、污点、依赖和回溯。
- 支持从节点发起重放。

**M5-03 漏洞详情和攻击链画布（P0）**

- 显示证据、前置条件、验证状态和修复建议。
- 推测边、疑似边和已验证边使用不同视觉状态。

**M5-04 报告导出（P1）**

- 导出 HTML/PDF/JSON；包含覆盖度、未覆盖原因、依赖模拟说明和审计信息。

**M5-05 GUI 实时事件与安全边界（P0）**

- 通过 SSE 接收扫描增量，断线后使用幂等查询补偿；展示策略、依赖模式和停止原因。
- 对代码、配置、SQL 和模型文本统一转义和脱敏；危险操作按钮显示审批状态。
- 验收：低权限账号不能通过前端接口读取其他项目或未脱敏轨迹；事件重连不会重复计数。

- 当前状态：Control Plane REST/SSE MVP slice 已完成并通过本地验收。实现范围是 `/api/v1` 版本化 DTO、SQLite 控制面、鉴权、幂等项目/制品/扫描创建、分块上传恢复和 SSE 事件流；Worker task、租约、checkpoint、trace、上传会话以及 V011 的幂等绑定、流水线 cursor、probe plan 已纳入单节点恢复语义，但不等同于生产级 RBAC 或分布式队列。
- 路由和协议：写操作使用 `X-Sentinel-Authorization` 或 `Authorization: Bearer`，扫描 body 须显式 `authorized: true`，制品登记显式 `authorized=false` 时拒绝；`Idempotency-Key` 用于项目/制品/扫描、audit-run、动态任务、finding replay 和 `sandbox_probe` job 绑定去重。`GET /api/v1/scans/{id}/events` 支持 `Last-Event-ID`，终态为 `ScanCompleted`/`TaskStopped`，断线后以幂等 GET 补偿。
- 静态限制：health/DTO 明确持久化模式、`STATIC_METADATA_ONLY`、`MOCK`；Control Plane 不执行制品、不把预算内调用图/跨方法污点当作运行时事实，也不把协议替身、动态路径、沙箱或 LLM 输出升级为 `VERIFIED`。

### M6：验收与硬化

**M6-01 基准样例集（P0）**

- 建立包含安全和非安全分支的可控 Java 样例。
- 每个样例有预期入口、路径、sink 和攻击链。

**M6-02 复现和回归测试（P0）**

- 同一制品、同一输入和同一快照可重复得到相同结论。

**M6-03 性能和安全压测（P1）**

- 验证并发 Worker、轨迹压缩、沙箱逃逸防护和数据脱敏。

- 注：沙箱逃逸、宿主机访问和策略绕过属于 M2 的 P0 安全门槛；M6-03 的 P1 只覆盖规模、性能和长期稳定性，不能用来推迟隔离基线。

## 4. Definition of Done

每个功能完成必须满足：

- 有自动化测试或可复现样例；
- 有结构化数据和 GUI 展示；
- 有审计日志；
- 失败时有明确错误和停止原因；
- 不绕过安全策略；
- 结果可重放且能定位到制品版本。

## 5. MVP 衡量指标

- 入口发现召回率；
- 方法/分支/sink 覆盖率；
- 数据库表字段识别准确率；
- 已验证漏洞的复现成功率；
- 攻击链有效率和误报率；
- 单项目平均分析时间；
- 依赖模拟后继续执行的路径比例。

建议在基准样例集上为指标设置可执行的首版门槛（后续按实测校准）：入口发现召回率 ≥90%，已知 sink 到达率 ≥80%，已验证结果重复复现率 ≥95%，攻击链候选去重准确率 ≥90%，单项目默认扫描在 15 分钟预算内完成。指标必须注明样例规模、框架版本、是否使用模型推断以及“模拟依赖”范围，避免跨环境比较造成误导。

## 6. 依赖关系、发布闸门与回滚

### 6.1 关键依赖

M0 的策略、任务和审计模型是所有后续里程碑的前置条件；M1 的运行画像和入口目录先于 M2 的动态探测；M2 的可重放轨迹和 JDBC/文件替身先于 M3 的回溯；M3 的结构化证据先于 M4 的漏洞判定和攻击链；M5 GUI 只能展示已经版本化的事实，不得自行推断漏洞。

### 6.2 发布闸门

每个里程碑结束时必须通过自动化基准、权限/租户负向用例、依赖不可用用例、模型不合规输出用例和审计日志完整性检查。任何 P0 安全测试失败都阻止进入下一阶段；升级 Agent、字节码插桩或图谱 schema 时必须支持兼容读取和可回滚版本。

### 6.3 MVP 出口标准

MVP 仅在演示项目和至少一个真实（已授权、脱敏）Spring Boot 制品上完成导入、静态建模、沙箱执行、依赖模拟、可重放轨迹、漏洞证据和报告闭环后结束。无法启动或仅有静态分析的制品须单独标识，不得计入动态成功率。

## 7. 演示项目建议

准备一个故意包含以下逻辑的 Spring Boot 应用：

1. `/api/upload`：根据用户输入保存文件；
2. `/api/info`：返回文件或服务器路径信息；
3. `/api/read`：读取指定文件；
4. `/api/run`：将指定内容交给进程执行；
5. 一个需要管理员角色的分支；
6. 一个依赖数据库记录才能进入的业务状态。

演示目标不是执行真实破坏性命令，而是让平台展示：前置 AI 识别入口和依赖、数据库使用替身继续执行、权限前置条件被保留、各条路径产生证据，并由中枢生成“候选攻击链/已验证攻击链”的区别。
