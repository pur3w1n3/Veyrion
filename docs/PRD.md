# 溯脉 · Veyrion 产品需求文档

正式产品名：**溯脉 · Veyrion**（英文：**Veyrion**）。Java 包名、Maven artifactId、内部 service name 和 `/api/v1` 路由继续使用兼容标识；商标和域名尚需检索。

## 1. 文档信息

- 版本：0.1（产品草案）
- 状态：待评审
- 适用范围：JAR、WAR、CLASS 形式的闭源 Java/JVM 应用
- 产品定位：AI 驱动的代码理解、路径探索、运行时验证和攻击链推理平台

## 1.1 核心术语

- **入口（Entrypoint）**：任何能由应用边界之外触发的 HTTP、WebSocket、消息、RPC、定时任务或管理接口。内部 service 方法只有在存在外部可达链路时才计为入口链的一部分。
- **路径（Path）**：从入口、输入和身份出发，经过转换、分支、状态变化到副作用或返回结果的一条可重放执行轨迹。
- **依赖模式（Dependency Mode）**：`MOCK`（规则/模拟器）、`REPLAY`（录制回放）、`SHADOW`（影子环境）或 `REAL_READONLY`（受控只读真实连接）。
- **证据（Evidence）**：请求、快照、调用栈、字节码位置、污点事件、依赖访问、覆盖率和输出的可引用记录。
- **验证状态**：`STATIC_INFERRED`、`DYNAMIC_SUSPECTED`、`VERIFIED`、`UNREACHED`。状态升级必须有新增证据，不能由模型单独升级。

## 2. 产品愿景

用户提供已获授权的闭源应用制品，平台先由前置 AI 通读字节码、反编译结果、配置和运行时注册信息，建立业务逻辑、对外入口、参数、权限、租户和外部依赖地图；随后在隔离沙箱中尽可能深入执行每条业务路径。

平台的第一原则是“代码逻辑优先”：数据库、第三方服务、时间、随机数等不可控因素不应让路径探索提前终止。系统优先使用模拟器、快照、录制回放或受控替身完成逻辑执行，同时记录真实数据依赖（例如具体表和字段），在结果中明确标记依赖和前置条件。

平台不承诺数学意义上的所有路径都能终止或全部覆盖，而是提供覆盖度、未覆盖原因、停止条件和可重复证据。

## 3. 目标与非目标

### 3.1 产品目标

1. 尽可能完整地发现 HTTP、WebSocket、GraphQL、gRPC、消息监听器和管理入口。
2. 对每个入口建立参数、权限、状态和数据流模型。
3. 通过覆盖率反馈、约束求解和状态快照进行“洪水式”路径探索。
4. 对文件、网络、命令、脚本、反射、反序列化、模板和数据库等敏感流向进行 AI 辅助分析。
5. 将独立漏洞合并为有证据的攻击链，并区分“推测”“疑似”“已验证”。
6. 让用户可以在 GUI 中查看、暂停、回放和审计每条路径。

### 3.2 非目标

- 不在未经授权的真实生产系统上自动攻击。
- 不把 LLM 的自然语言判断作为唯一漏洞依据。
- 第一阶段不追求支持所有语言、所有框架和所有协议。
- 不以“100% 代码覆盖”作为产品承诺；必须报告未覆盖区域和原因。

## 4. 目标用户与场景

- 企业安全团队：对供应商交付的闭源 JAR/WAR 做上线前验证。
- 甲方研发团队：验证内部微服务和遗留系统的高危调用链。
- 渗透测试团队：快速理解闭源应用并生成可复现证据。
- 软件供应链团队：对第三方组件和插件进行隔离审计。

典型场景：上传接口写文件、路径泄露接口和文件执行接口分别被发现后，平台自动在全局图中将它们串成潜在 RCE 链，并提示所需权限、租户和业务状态。

## 4.1 角色与权限

- **项目管理员**：上传制品、配置启动画像、批准网络和危险操作策略。
- **安全分析师**：启动/暂停扫描、审阅轨迹、确认或驳回发现、导出报告。
- **研发修复者**：只能查看分配给自己的发现和脱敏证据，不能读取原始制品或凭据。
- **审计员**：只读查看操作、策略变更、模型调用和结果状态变更。

所有角色均受项目和租户边界限制；模型服务只能接收经过策略批准的脱敏数据。

## 5. 核心用户流程

1. **创建项目与授权**：确认制品来源、测试范围、网络白名单、破坏性操作策略和数据保留期限。
2. **导入制品**：上传 JAR/WAR/CLASS，选择 Java 版本、启动命令、配置模板和依赖模拟策略。
3. **前置 AI 建模**：生成入口清单、业务模块图、参数模型、权限矩阵、状态机、数据库/外部服务依赖图和高风险 sink 清单。
4. **计划评审**：用户可以修改入口、身份、租户、模拟数据和资源预算后启动扫描。
5. **沙箱探索**：平台执行基础请求，依据覆盖率、异常、污点轨迹和分支约束不断生成新输入；约束失败时回溯到最近可行节点。
6. **AI 分析与串联**：子 Agent 分析每条轨迹，中枢知识图谱去重、关联并提出攻击链；验证 Agent 只执行安全、可回放的验证动作。
7. **结果审阅**：用户查看入口地图、路径时间线、数据流、漏洞详情和攻击链画布。
8. **导出与复测**：导出报告、修复建议和脱敏证据；替换新版本制品后复用原路径进行回归验证。

## 6. 功能需求

### 6.1 制品与运行画像

- 支持 JAR、WAR、CLASS 和依赖目录导入。
- 自动识别 Java 版本、框架、入口注册方式、启动参数和配置项。
- 支持手工补充配置、环境变量、模拟服务和认证信息。
- 为每次扫描生成不可变制品版本和运行画像。

### 6.2 前置 AI：业务与入口建模

前置 AI 必须输出结构化结果，而非只有摘要：

- `EntryCatalog`：入口、协议、方法、参数、认证要求、所属模块。
- `BusinessFlow`：关键业务对象及其创建、读取、修改、删除关系。
- `PermissionMatrix`：角色、租户、状态和入口之间的前置条件。
- `DependencyMap`：数据库表/字段、外部 HTTP、文件、缓存、消息队列等依赖。
- `SinkCatalog`：敏感操作及其可达入口。
- `ExplorationPlan`：优先级、输入生成策略、预算和模拟策略。

前置 AI 的结论必须标注来源：反编译代码、字节码、配置、运行时注册或模型推断。

前置 AI 的工作分为两个阶段：

1. **事实提取**：由解析器、字节码分析和运行时探针生成不可由模型篡改的事实；
2. **业务解释**：模型根据事实生成业务对象、状态和优先级，并为每条推断附上 `evidenceRefs`。

模型输出中不得出现没有证据引用的“确定性”结论。闭源制品中的注释、字符串、配置和接口返回值均视为不可信输入，必须防范提示注入，不得让制品内容改变 Agent 的工具权限或扫描策略。

### 6.3 依赖可观测化与替身

依赖处理采用以下优先级：

1. **模拟器**：数据库、HTTP、缓存、消息队列默认使用可编程替身。
2. **快照/录制回放**：用户提供测试数据或首次安全录制的响应，后续离线重放。
3. **受控真实连接**：仅在用户明确允许、白名单和只读策略同时满足时启用。

无论使用哪种模式，都要记录：

- 数据库：库、表、字段、读写类型、查询模板和脱敏样例；
- HTTP：目标服务、路径、方法、请求/响应摘要；
- 文件：路径模式、读写操作和文件类型；
- 其他依赖：队列、缓存、时间、随机数和环境变量。

“绕过数据库连接错误”只表示用替身继续执行代码逻辑，不得把替身结果误报为真实数据可用性；报告中必须显示“依赖已模拟”。

替身返回值必须带有来源和可信度：

| 来源 | 含义 | 是否可升级为真实验证 |
| --- | --- | --- |
| 用户提供快照 | 来自用户脱敏导入的数据 | 只能证明逻辑可执行 |
| 录制回放 | 来自授权环境的历史响应 | 需确认版本和状态一致 |
| 规则生成 | 根据类型/SQL/状态生成 | 不能单独证明真实影响 |
| 真实只读 | 白名单内的只读连接 | 可作为运行时证据，但仍需标注环境 |

如果替身使分支成立，结果的前置条件必须包含 `dependencyMode` 和 `dependencyAssumption`；这样用户能区分“代码存在风险”和“当前环境可直接利用”。

### 6.4 洪水式路径探索

- 入口级、参数级、分支级和状态级覆盖率统计。
- 类型感知、边界值、语法变异、污点定向和约束求解输入。
- 任务队列支持优先级、暂停、取消、重试和快照恢复。
- 失败原因分类：类型约束、权限、租户、业务状态、外部依赖、超时、异常和循环。
- 每次回溯保留父路径、约束条件、输入和覆盖率变化。
- 对权限/租户/业务状态路径继续执行，但结果中必须标注前置条件。
- 对疑似死循环或不终止路径使用时间、指令数、状态重复和资源上限停止，并报告停止原因。

每个扫描计划都必须显式声明预算：总时长、单路径时长、最大分支数、最大状态数、并发 Worker 数和模型调用额度。预算耗尽不是错误，必须生成一条可查询的 `UNREACHED` 记录。

### 6.5 AI 分析与攻击链

- 子 Agent 仅读取脱敏源码片段、字节码摘要、结构化轨迹和工具查询结果。
- 每个结论必须返回类型、证据、前置条件、置信度、CWE 和建议复现任务。
- 中枢按规范化的 source/transform/sink/impact 合并结果。
- 攻击链必须至少包含两条有证据的边；推测边和已验证边视觉上区分。
- 低置信度结果进入待验证队列，不直接列为确认漏洞。

## 7. GUI 页面

GUI 采用独立的 React/TypeScript 前端，Java 只提供分析控制面和版本化 API；详细交互、视觉状态和页面验收见 [GUI 设计规范](GUI_DESIGN.md)。

- 项目总览：扫描状态、入口数、覆盖度、漏洞和攻击链。
- 入口地图：按协议、模块、权限和风险筛选。
- 路径探索器：请求、参数、调用栈、分支、污点和外部依赖时间线。
- 业务/数据流图：从参数到表字段、文件、网络和执行 sink 的关系。
- 攻击链画布：跨接口串联、前置权限和验证状态。
- 漏洞详情：证据、复现、影响、修复和关联路径。
- 沙箱控制台：启动画像、依赖模式、资源限制、任务日志和快照。
- 策略中心：授权、白名单、破坏性操作、脱敏和数据保留。

所有实时进度通过 SSE/WebSocket 事件更新，最终状态以幂等查询接口为准；前端不直接连接数据库、对象存储、沙箱或模型服务。

## 8. 结果分级

- **已验证**：在沙箱中可重复达到敏感 sink，并有完整轨迹。
- **动态疑似**：运行时达到关键中间点，但影响尚未闭合。
- **静态推测**：静态图显示可达，但尚未成功执行。
- **未覆盖**：存在路径或依赖，但受预算、权限、状态或非终止条件影响。

所有结果均显示覆盖度和停止原因，禁止只展示一个没有上下文的风险分数。

### 8.1 结果最小证据集

标记为 `VERIFIED` 至少需要：

- 可重放的制品版本和运行画像；
- 入口、输入、身份/租户和业务状态；
- 完整或明确截断的调用/污点轨迹；
- 到达的敏感 sink 和实际副作用摘要；
- 所有外部依赖及其模式；
- 快照、任务和日志引用；
- 沙箱资源和停止条件未被突破的证明。

### 8.2 用户操作

用户可以对结果执行：确认、驳回、标记误报、要求复测、调整前置条件或关联到已有攻击链。每次人工改变都保留前后值、操作者和理由。

## 9. 安全、合规和验收

- 扫描前必须确认授权和范围；所有任务写入审计日志。
- 默认禁止外网、真实破坏性 payload 和跨租户访问。
- 原始制品、配置、凭据和轨迹加密存储，并支持自动销毁。
- 验收指标：入口发现召回率、有效路径覆盖率、已验证结果复现率、攻击链去重准确率、误报率和平均分析耗时。
- 第一版验收场景：Spring Boot 应用中至少包含上传、路径读取、数据库查询和命令执行相关逻辑，能够完成“导入—建模—探索—串联—报告”闭环。

## 10. 威胁模型与产品边界

平台的主要风险不只有被测应用本身，还包括恶意制品、恶意配置和被测代码中的提示注入。制品可能尝试读取宿主机、探测内网、消耗资源或诱导 Agent 执行越权操作。因此：

- 制品、反编译文本和运行时字符串均视为不可信输入；它们不能改变 Agent 的系统提示、工具权限或扫描策略。
- Agent 只能调用版本化、参数校验后的分析/沙箱工具；工具调用必须经过策略中心和审计日志，禁止把模型输出直接拼接为宿主机命令。
- “安全验证”默认采用无害标记、模拟文件和回显探针；真实命令、外带网络、删除/写入真实数据等动作必须由用户逐项批准，并记录审批人和范围。
- 生成的身份、租户和业务状态是合成测试状态，不代表真实授权已经绕过；报告必须同时显示“代码可达性”和“真实环境可利用性”两种结论。

产品部署分为本地/私有化和受控云端两种模式。原始制品、凭据和未脱敏轨迹默认只留在客户环境；云端模型只接收脱敏、最小化的结构化上下文。租户隔离、密钥轮换、删除证明和数据保留期限属于商业版上线门槛。

## 11. 非功能需求与结果语义

- 可重放性：同一制品哈希、运行画像、快照和输入种子应得到相同的路径结论；模型解释允许版本变化，但事实轨迹不可变。
- 可解释性：每个结论都能回跳到类/方法/字节码位置、请求、快照和依赖记录；找不到证据时只能标记为推测。
- 可用性：扫描任务支持幂等、断点恢复和取消；Worker 崩溃不得丢失已提交证据。
- 隔离性：不同项目之间的制品、凭据、轨迹、模型上下文和沙箱网络命名空间必须隔离。
- 可扩展性：框架适配器、sink 规则、输入生成器、依赖替身和 Agent 使用版本化插件接口。
- 性能预算：MVP 单任务默认 15 分钟、2 vCPU、4 GB 内存和 2 GB 临时磁盘，超限必须给出 `stopReason`；具体上限可按项目策略调整。
- 入口覆盖率、路径覆盖率、字段识别准确率和攻击链有效率必须在基准样例集上定义基线与目标值，不能只展示无阈值的百分比。

## 12. 关键验收场景

1. 数据库不可连接时，平台仍能执行到文件写入逻辑，同时显示具体表/字段和 `MOCK` 模式。
2. 只有管理员权限可达的命令执行分支能够被执行，但报告明确显示权限前置条件，不标记为匿名可利用。
3. 同一漏洞在不同入口产生的证据能够去重，并在攻击链中保留两条入口引用。
4. 超时、状态循环或预算耗尽后，用户能看到停止原因、最近快照和未覆盖节点。
5. 在制品中嵌入诱导模型越权的注释或字符串时，Agent 仍不能获得额外工具或网络权限。
